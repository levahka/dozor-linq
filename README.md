# ДОЗОР — видеоконтроль поведения на производстве на ИИ-ускорителях LinQ

Решение кейса LinQ (ХайТэк) хакатона «Открой#Моспром», 23–25.10.2026.

Система смотрит в видеопотоки камер вместо оператора, распознаёт **опасное поведение людей во времени**
и в течение 1–2 секунд присылает **одно** оповещение с кадром-доказательством и фрагментом видео.
Нейросети выполняются на российском ускорителе **LinQ TPU**: видео не покидает предприятие.

## Что умеет

| № в кейсе | Паттерн | Как распознаётся | Критичность |
|---|---|---|---|
| 07 | Падение / человек лежит | поза (17 точек): угол корпуса плечи→бёдра > 55°, + «резкое падение», если секунду назад стоял | критично |
| 07 | Неподвижность, возможна потеря сознания | лежит и центр тела не смещается > 12 % роста за 8 с | критично |
| 02 | Опасное сближение с техникой | детектор техники + трекинг её скорости; человек ближе 0,6 роста к **движущейся** машине | критично |
| — | Вход в опасную зону | полигон на кадре, рисуется мышкой; может действовать **по расписанию** (с 07:55 до 12:00) | настраивается |
| 01 | Бег, резкие перемещения | скорость трека в «ростах человека в секунду» — не зависит от расстояния до камеры | предупреждение |
| 03 | Телефон при работе/на ходу | детектор телефона + рядом с кистью/ухом по позе | предупреждение |
| 04, 05, 06, 08 | Курение/огонь, перелезание, высота без привязи, переноска груза | архитектура готова: новый файл-правило в `sv/rules/`, остальное не меняется | — |

**Антидребезг и дедупликация** (общие для всех правил, `sv/rules/base.py: EventEngine`):
признак должен держаться `confirm_s` секунд в ≥ `confirm_ratio` кадров → одно событие; пока нарушение длится,
повторов нет; событие закрывается, если признак пропал на `clear_s`; после этого тот же человек
(или рамка на том же месте, если трек сменил номер) молчит `cooldown_s`. Все параметры — на камеру, из интерфейса.

## Интерфейс (http://localhost:8000)

* **Мониторинг**: живое видео со скелетами, зонами и треками; лента событий; критичная тревога всплывает со звуком;
  в карточке события — кадр и GIF-фрагмент, статусы «подтверждено / ложное / передано мастеру», комментарий.
* **Журнал**: фильтры по камере, типу, статусу, критичности, времени; выгрузка CSV для Excel (доказательная база для ОТ и инспекции).
* **Аналитика**: нарушения по типам, камерам, часам суток, дням, зонам; время реакции; **точность по отметкам оператора**.
* **Камеры и зоны**: рисование полигонов на кадре, расписание зон, включение правил и их пороги — без правки кода и перезапуска.
* **Производительность**: живые замеры FPS и задержки по стадиям (предобработка / TPU head / CPU tail / постобработка),
  расчёт «сколько камер выдержит один ускоритель» и «сколько узлов на цех».
* **Telegram** мастеру смены: `notify.telegram` в `config/config.yaml` (кадр + ссылка на событие).

## Быстрый старт (Windows, без GPU)

```
run.bat
```
Скрипт создаст `.venv`, поставит зависимости и откроет браузер. Нужен Python 3.10+ (python.org, «Add to PATH»).

Вручную / Linux:
```
python -m venv .venv && .venv\Scripts\activate      # Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m sv.server --port 8000
```

Камеры — в `config/config.yaml` (`source`: RTSP-адрес, файл, папка со стоп-кадрами или `0` для веб-камеры).
В комплекте три демо-источника в `data/`: цех с разметкой (зона), стоянка (техника), повёрнутый ролик (лежащий человек).
**Для защиты снимите свои ролики**: падение на мат, неподвижное лежание, бег, телефон у уха, проход рядом с машиной.

## Архитектура

```
 камера (RTSP/файл/кадры) ─► FrameSource (свежий кадр, реальный темп)
   └─► YOLO11n-pose (люди + 17 точек) ─┐        ┌─ LinQ TPU: head (свёртки, INT8)
   └─► YOLO11n (техника, телефон) ─────┤  ◄─────┤
                                        │        └─ CPU: tail (декодер головы) + NMS
   ► ByteTrack-lite (track_id) ► TrackHistory (15 с)
   ► правила-модули (fall, immobile, running, zone, proximity, phone, …)  ← параметры камеры
   ► EventEngine (подтверждение во времени, антидребезг, дедупликация)
   ► SQLite-журнал + кадр + GIF ► WebSocket (браузер) + Telegram
```

* `sv/infer/runtime.py` — бэкенды: `cpu` (onnxruntime), `split` (head+tail на CPU), `linq` (pytpu), `remote` (TPU на другой машине).
* `sv/infer/yolo.py` — letterbox, декодирование, NMS — **одинаковые для CPU и TPU**, поэтому перенос не меняет логику.
* `sv/tracker.py` — свой трекер (IoU + близость центров, работает и на 2–3 к/с), без AGPL-зависимостей.
* `sv/rules/` — правила; новое нарушение = новый класс с `@register`.
* `sv/server.py` — FastAPI: REST + WebSocket + MJPEG; `web/` — интерфейс без сборки и без внешних CDN (работает в закрытом контуре).

## Перенос на LinQ TPU (сделано и проверено на облачном стенде)

**Статус на 23.10:** обе сети скомпилированы (пресет O5) и выполняются на облачном LinQ организаторов.

| Модель | Совпадение TPU (INT8) с CPU (float), косинус | Детекции TPU vs CPU | Время расчёта на TPU (отчёт воркера) |
|---|---|---|---|
| YOLO11n-pose (люди + поза) | 0.987 (мин 0.951) | 3 из 3, рамки совпали 100 % | 1–57 мс |
| YOLO11n (техника, телефон) | 0.981 (мин 0.941) | 3 из 5, совпадение 80 % | до 57 мс |

Полный путь «ноутбук → облачный TPU → ноутбук» сейчас 7–9 с на кадр и упирается в канал VPN (~50 КБ/с).
В боевой схеме ускоритель стоит рядом с камерами, сети между ними нет. Сырые цифры: `linq/linq_bench_2026-10-23.json`.

### 1. Разрез модели (готово, файлы в `models/`)
`python tools/split_onnx.py models/yolo11n-pose.onnx` → `*.head.onnx` (на TPU), `*.tail.onnx` (CPU), `*.split.json`.
Head+tail проверены на совпадение с исходной моделью (расхождение 0).

### 2. Компиляция (готово: `models/*.head_b1_o5_h1m.tpu`)
SDK работает только в Linux + Python 3.12. На Windows: WSL Ubuntu 24.04 (`wsl --install -d Ubuntu-24.04 --web-download`).
Скрипт `linq/setup_wsl.sh` ставит всё сам и компилирует обе сети. Положите его рядом с папками `tpu_framework/` (SDK из кейса)
и `safety_vision/` и запустите `wsl -u root -- bash ./setup_wsl.sh`.
Важно: **SDK требует numpy 1.26.4** — с numpy 2.x компилятор падает с `The truth value of an empty array is ambiguous`.
Калибровка INT8 — на 48 реальных кадрах из `data/`, не на шуме.

### 3. Запуск на облачном LinQ (через RabbitMQ)
1. Подключить VPN хакатона (`Hakathon.ovpn`). Если параллельно работает другой VPN и пропадает интернет —
   использовать профиль без перехвата DNS: строки `pull-filter ignore "dhcp-option"` и `pull-filter ignore "block-outside-dns"`.
   Jupyter и брокер доступны по IP `10.0.114.30` (имя `hackathon.lin-q.ru` резолвит только DNS VPN).
2. Загрузить `.tpu` в Jupyter и скопировать в `/auto/cache/<логин>/`.
3. `pip install pika tpu_pycloud_format-0.0.1-py3-none-any.whl` (whl — из папки `packages` в Jupyter).
4. `config/config.yaml`: `backend.kind: rabbit`, `backend.rabbit.login: <логин Jupyter>`.
5. Проверка и замер: `python tools/bench_linq.py`.

Протокол — как в `examples/example.ipynb` организаторов (exchange `tpu.direct`, очередь `input`, заголовок с путём к программе).
Мы используем режим `raw=True`: тензоры передаются в родном формате TPU (int8, раскладка `[C/B, H, W, N, B]` из `metadata.json`
программы) — в 3–4 раза меньше трафика, чем float32. Кодирование/декодирование — `sv/infer/runtime.py: RabbitLinqRuntime`.

Другие режимы: `linq` — pytpu на машине с ускорителем; `remote` — свой HTTP-сервис `linq/tpu_server.py` рядом с TPU.

## Метрики

* `python tools/replay.py <видео> --camera cam01 --fps 5 --gt разметка.csv` — прогон без сервера,
  полнота/точность по событиям и задержка тревоги относительно разметки (`type;start_s;end_s`).
* В интерфейсе: точность по отметкам оператора, время «начало нарушения → тревога», FPS/задержка по стадиям.

## Лицензии

Веса YOLO11 (Ultralytics) — AGPL-3.0: для прототипа допустимо, для внедрения — коммерческая лицензия Ultralytics
или замена на модели Apache-2.0 (YOLOX, RT-DETR) — пайплайн не меняется, меняется только ONNX.
